## 1. 功能概述

### 1.1 背景

当前曲线图表窗口仅支持单一实例。用户无法同时打开多个曲线窗口来进行信号对比分析。

典型需求场景：
- 将不同 ECU 的信号分别放在各自窗口中对比观察
- 并行分析同一 CAN 总线上的不同信号组（如车速 vs 转速 vs 油门开度）
- 将参考信号固定在某个窗口，在另一个窗口中切换对比不同信号

### 1.2 设计目标

允许用户创建多个独立的曲线图表窗口，每个窗口管理自己的信号列表，互不干扰。

## 2. 当前架构限制

### 2.1 面板 ID 固定单实例

**位置**: [App.tsx](file:///e:/dev/canscope/frontend/src/App.tsx#L51-L61)

```ts
const PANEL_DEFS = [
  // ...
  { id: 'chart', title: '图形曲线', defaultVisible: false, ... },
  // ...
];
```

`useWindowManager` 的面板管理基于固定的 `id` 字符串（如 `'chart'`），每个 ID 只能存在一个面板实例。不支持同类型面板的动态创建和销毁。

### 2.2 全局信号列表

**位置**: [App.tsx](file:///e:/dev/canscope/frontend/src/App.tsx#L703-L706) / [types.ts](file:///e:/dev/canscope/frontend/src/types.ts#L96-L100)

```ts
// App.tsx
<SignalChart
  frames={frames()}
  signals={chartSignals()}  // 全局共享
  onRemoveSignal={handleRemoveSignal}
/>

// types.ts
export interface ChartSignal {
  canId: number;
  signalName: string;
  unit: string;
}
```

`chartSignals` 是全局的 `Signal`，所有图表组件共享同一份信号列表。开启多个窗口后需要每个窗口独立维护自己的信号列表。

### 2.3 项目持久化耦合

**位置**: [types.ts](file:///e:/dev/canscope/frontend/src/types.ts#L168)

```ts
export interface ProjectInfo {
  // ...
  chartSignals: ChartSignalJson[];  // 仅存储一份信号列表
  // ...
}
```

项目文件中仅存储一个 `chartSignals` 数组，多窗口场景下需要扩展为结构化存储。

## 3. 需求规约

### 3.1 多窗口创建

| 属性 | 说明 |
|------|------|
| 状态 | ❌ 未实现 |
| 描述 | 用户点击 Ribbon「曲线」按钮时，应创建一个新的曲线窗口实例（而非切换已有窗口的显示/隐藏）。每个窗口拥有独立标题（如「图形曲线 #1」「图形曲线 #2」），用户可自由拖动、缩放、关闭。 |
| 交互 | 点击 Ribbon 曲线按钮 → 创建新窗口；窗口关闭 → 销毁实例与对应信号列表 |
| 限制 | 建议设置最大窗口数上限（如 8 个），避免性能问题 |

### 3.2 独立信号列表

| 属性 | 说明 |
|------|------|
| 状态 | ❌ 未实现 |
| 描述 | 每个曲线窗口维护自己独立的 `ChartSignal[]` 列表。在信号树中点击信号时，需确定将信号添加到哪个窗口（当前激活的窗口，或通过某种方式指定目标窗口）。 |
| 待定 | 信号树添加信号时如何路由到目标窗口？选项：① 添加到最近激活的窗口 ② 信号树提供窗口选择下拉 ③ 拖拽信号到目标窗口 |

### 3.3 窗口标题与管理

| 属性 | 说明 |
|------|------|
| 状态 | ❌ 未实现 |
| 描述 | 每个窗口标题显示「图形曲线 #N」或用户自定义名称。任务栏对应显示多个曲线窗口条目，点击可切换激活。 |
| 实现建议 | 窗口 ID 生成规则：`chart-{uuid}` 或 `chart-{n}`（递增序号复用） |

### 3.4 项目持久化扩展

| 属性 | 说明 |
|------|------|
| 状态 | ❌ 未实现 |
| 描述 | 保存/打开项目时，需将所有曲线窗口的信号列表、窗口位置和大小一并持久化并恢复。 |
| 数据结构建议 | `chartWindows: { id: string, title: string, signals: ChartSignalJson[], position: WindowRect }[]` |

## 5. 实现路径

分为两个阶段：

### 阶段一：单窗口 UI 定稿（当前）

1. 确定单曲线窗口的完整 UI 布局与交互设计

1. 改造 `useWindowManager`，支持同类型面板的多实例管理
2. 将全局 `chartSignals` 状态迁移为窗口级作用域
3. 实现「新建窗口」按钮 / 菜单，窗口 ID 动态生成
4. 扩展项目持久化结构，支持多个图表窗口的保存与恢复
5. 信号树交互适配多窗口场景
6. 实现窗口关闭时的资源清理

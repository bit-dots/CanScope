## 1. 概述

### 1.1 文档目的

本文档定义 CanScope 的目标用户、使用场景、功能需求和非功能需求，为后续的详细设计和开发提供基准。

### 1.2 产品定位

跨平台 CAN 总线**离线回放分析工具**，首阶段不依赖任何 CAN 硬件。后期可扩展为支持实时硬件接入的全功能分析平台。

## 3. 使用场景

### 场景 1：快速查看 CAN 日志（基础）

> 小明拿到一段车辆路试录制的 ASC 日志（500MB），想快速浏览总线上发生了什么。

**操作流**：
1. 打开 CanScope
2. 拖入 ASC 文件
3. 在报文列表里滚动浏览，按 CAN ID 过滤
4. 加载 DBC 文件后，列表自动显示解码后的信号值

**关键体验**：大文件秒开、滚动不卡顿。

---

### 场景 2：追踪特定信号的时序变化（信号分析）

> 工程师怀疑某个车速信号在某时刻跳变异常。

**操作流**：
1. 打开 ASC 文件 + 对应 DBC
2. 在 DBC 信号树中找到 "VehicleSpeed"
3. 双击信号，打开信号曲线面板
4. 拖动时间轴到异常发生的时间段
5. 观察曲线，确认跳变点和幅度

**关键体验**：选中信号即可看到曲线，无需额外配置；曲线跟随回放实时更新。

---

### 场景 3：对比两次测试的 CAN 数据（对比分析）

> 测试工程师录制了"正常"和"故障"两份 trace，需要找出差异。

**操作流**：
1. 打开两份 trace（Trace A 作为基准、Trace B 作为对比）
2. 对齐时间轴（使用某个同步 CAN ID 的首次出现作为对齐点）
3. 差异高亮模式：B 中新增、缺失、数据值不同的帧用不同颜色标出
4. 过滤只看某个 CAN ID 的差异

**关键体验**：差异一目了然，不用肉眼逐帧比对。

---

### 场景 4：离线回放实际路试数据（复现分析）

> 路试工程师带着录好的数据回到办公室，需要像"看录像"一样逐帧复现当时的 CAN 总线状态。

**操作流**：
1. 加载 ASC 文件 + DBC
2. 点击播放，观察报文列表实时滚动、信号曲线实时绘制
3. 倍速播放（2x / 5x / 10x）跳过无关时段
4. 发现异常时暂停，逐帧步进分析
5. 循环播放 A-B 段，反复观察关键区间

**关键体验**：回放像视频播放器一样流畅，时间轴响应灵敏。

---

### 场景 5：数据清洗与格式转换（数据工程）

> 工程师需要将 Vector 录制的 ASC 文件转成 CSV 导入 Python/MATLAB 做进一步分析。

**操作流**：
1. 加载 ASC 文件
2. 按 CAN ID 或时间范围裁剪
3. 导出为 CSV（带 DBC 解码信号列）
4. 在外部工具中继续分析

**关键体验**：导出操作简单，格式互转不出错。

## 6. 领域模型

```
┌──────────────────────────────────────────────────────────────┐
│                         领域模型                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌─────────┐    1..*    ┌──────────┐   1..*    ┌─────────┐  │
│  │  Trace   │──────────▶│ CanFrame │◀──────────│  DBC    │  │
│  │ (文件源)  │  contains  │          │  decodes  │ (数据库) │  │
│  └─────────┘           └────┬─────┘           └────┬────┘  │
│                             │                      │        │
│                             │                      │ 1..*   │
│                     ┌───────▼───────┐      ┌───────▼───────┐│
│                     │ DecodedFrame  │      │  DbcMessage   ││
│                     │ (解码后帧)     │      │  (报文定义)    ││
│                     └───────┬───────┘      └───────┬───────┘│
│                             │                      │ 1..*   │
│                             │ 1..*         ┌───────▼───────┐│
│                             └──────────────│  Signal       ││
│                               contains     │  (信号定义)    ││
│                                            └───────────────┘│
│                                                              │
│  ┌─────────┐  1     1..*  ┌──────────┐                      │
│  │Playback  │─────────────│ Timeline  │                      │
│  │ Engine   │  controls   │(时间轴)    │                      │
│  └─────────┘             └──────────┘                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 6.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| **Trace** | 一段 CAN 通信记录（来自文件或实时源） | 文件名、格式、通道数、起始时间、总帧数、总时长 |
| **CanFrame** | 一帧原始 CAN 报文 | 时间戳、总线号、CAN ID、扩展帧标志、远程帧标志、CAN FD、DLC、数据字节 |
| **DBC** | DBC 数据库文件的内存表示 | 文件名、报文列表、信号列表 |
| **DbcMessage** | DBC 中对一条 CAN 报文的定义 | CAN ID、报文名、DLC、发送节点、信号列表 |
| **Signal** | DBC 中对一个信号的定义 | 信号名、起始位、长度、字节序、符号、缩放因子、偏移量、最小值、最大值、单位、值表 |
| **DecodedFrame** | 一帧经过 DBC 解码的 CAN 报文 | CanFrame 引用 + 解码后的信号值映射（SignalName → PhysicalValue） |
| **PlaybackEngine** | 回放控制器 | 状态、播放速度、当前时间戳、循环区间、缓冲区 |
| **Timeline** | 时间轴 | 总时长、当前游标位置、书签列表、A-B 标记 |

**差异化机会**：

1. **极致的大文件性能** — 竞品加载 500MB+ ASC 普遍慢（10-30s），虚拟滚动几乎是空白
2. **Trace 对比分析** — 只有 BUSMASTER 支持，且界面老旧
3. **现代化 UI** — 竞品全是 Qt 风格，Tauri + Web 前端的视觉体验有代差
4. **脚本扩展** — 竞品无插件系统，用户无法自定义分析逻辑
